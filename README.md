# 🧠 Novita AI Batch Processor

Streamlit‑приложение для пакетной работы с текстами через API Novita AI. Интерфейс состоит из отдельных вкладок для генерации контента, перевода, постобработки, фильтрации данных и работы с тегами. Все операции выполняются локально в браузере: вы загружаете CSV/TXT файлы, задаёте промпты и параметры модели, запускаете обработку и скачиваете результат.

---

## 📦 Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export NOVITA_API_KEY="ваш_ключ" # либо создайте .streamlit/secrets.toml
streamlit run app.py
```

## 🗂️ Структура приложения

`app.py` — единственный скрипт, который:

- Конфигурирует базовые эндпоинты Novita и параметры генерации.
- Реализует вспомогательные функции (`custom_postprocess_text`, `process_file`, `process_translation_file`, `clean_text` и др.).
- Описывает 7 вкладок интерфейса (обработка, перевод, разделение, постобработка, выбор столбцов, удаление кавычек, теги).
- Показывает прогресс-бар и примерное оставшееся время при работе с большими файлами.

---

## 📑 Вкладки интерфейса

- **🔄 Обработка текста** — одиночные промпты и пакетная обработка заголовков/текстов из файла. Поддерживается параллельная загрузка и выгрузка CSV/TXT.
- **🌐 Перевод текста** — аналогичный пайплайн, но с автоформированием промпта вида “Translate from X to Y”.
- **📂 Разделение файла** — просто разбивает CSV/TXT на части фиксированного размера.
- **🧹 Постобработка** — удаление заранее указанных паттернов и продвинутый санитайзинг заголовков (эмодзи, иероглифы, домены, нежелательная пунктуация, комментарии модели, проверка длины и замены родственных связей).
- **🗂️ Выбор столбцов** — фильтрация загруженного CSV (поддерживаются только `id`, `title`, `rewrite`, `cleaned`) и экспорт с разделителем `|`.
- **❌ Удаление кавычек** — удаляет `"` из колонок `id` и `cleaned` в `|`‑разделённых CSV.
- **🏷️ Теги** — автодополнение до 5 тегов из списка разрешённых значений для каждой строки CSV.

## 🧾 Техническая документация по вкладкам

### 🔄 Обработка текста (`tabs[0]`)
- **Назначение**: генерация ответов для одиночного промпта или батч‑переписка заголовков/описаний из файла.
- **UI**: выбор пресета (`PRESETS`), обновление списка моделей через `get_model_list`, настройка гиперпараметров, поле одиночного промпта, загрузчик CSV/TXT с кастомными `delimiter` и названиями колонок.
- **Алгоритм батча**: `process_file` читает `title_col`, формирует сообщения `system + user`, и с помощью `ThreadPoolExecutor` вызывает `process_single_row` → `chat_completion_request`. Результат постобрабатывается через `custom_postprocess_text` и пишется в колонку `rewrite`.
- **Параллельность**: `chunk_size` фиксирован (10), `max_workers` выбирается пользователем (1–20). По завершении каждого чанка обновляется прогресс‑бар и расчёт ETA.
- **Валидации**: проверка наличия API‑ключа, непустых промптов, успешного парсинга файла. При ошибке чтения файла выводится `st.error`.
- **Экспорт**: кнопки для выгрузки `csv` или `txt` (второй использует `sep="|"`, `header=False`).

### 🌐 Перевод текста (`tabs[1]`)
- **Назначение**: перевод содержимого указанной колонки между выбранными языками.
- **UI**: отдельный пресет/параметры, выбор исходного и целевого языка (сообщение, если совпадают), отдельный загрузчик файла и селекторы колонок `id`/`title`.
- **Алгоритм**: `process_translation_file` повторяет батч‑логику, но в промпт автоматически добавляется строка `Translate the following text from {source} to {target}`. Ответы сохраняются в колонку `translated_title`.
- **Выход**: скачивание в `csv` или `txt` (аналогично вкладке обработки).
- **Особые проверки**: запрещён запуск при совпадающих языках или невыбранной колонке для перевода.

### 📂 Разделение файла (`tabs[2]`)
- **Назначение**: нарезка загруженного CSV/TXT на части по количеству строк.
- **UI**: числовое поле `split_size` (по умолчанию 5000), один `file_uploader`.
- **CSV**: читается целиком в `pandas`, определяется количество частей `ceil(total_rows / split_size)`, каждая выгружается отдельной кнопкой `part_i.csv`.
- **TXT**: файл разбивается построчно; создаётся строка диапазона, которая сохраняется в `part_i.txt`.
- **Ошибки**: любые исключения чтения/парсинга ловятся и отображаются через `st.error`.

### 🧹 Постобработка (`tabs[3]`)
- **Назначение**: очистка текста по пользовательским паттернам + встроенный санитайзинг.
- **UI**: поле `text_area` с дефолтным списком паттернов, загрузчик CSV/TXT.
- **CSV сценарий**: пользователь выбирает колонку для очистки → `process_postprocessing_file` применяет `clean_text` к каждой строке и создаёт колонку `cleaned`, которую можно скачать в CSV.
- **TXT сценарий**: каждая строка обработана функцией `clean_text`, предпросмотр ограничен первыми 1000 символами.
- **`clean_text` пайплайн**: удаление кастомных паттернов, доменных имён (`remove_domains`), служебных комментариев (`strip_commentary_phrases`), стоп‑замены родственных связей, фильтрация эмодзи/иеороглифов/символов, фиксация пробелов, тримминг до 100 символов.

### 🗂️ Выбор столбцов (`tabs[4]`)
- **Назначение**: оставить лишь нужные колонки из CSV с результатами обработки.
- **UI**: загрузчик CSV, предпросмотр, мультиселект из ограниченного набора (`id`, `title`, `rewrite`, `cleaned`) — показываются только реально существующие колонки.
- **Экспорт**: `pandas.DataFrame.to_csv` с `sep="|"`, `quoting=csv.QUOTE_NONE`, `escapechar="\"`, что гарантирует отсутствие кавычек в выходных данных.
- **Ошибки**: если ни один ожидаемый столбец не найден, выводится `st.error`; при пустом выборе — `st.warning`.

### ❌ Удаление кавычек (`tabs[5]`)
- **Назначение**: убрать двойные кавычки из колонок `id` и `cleaned` в `|`‑разделённом CSV.
- **Алгоритм**: CSV читается с `sep="|"`, далее для каждой целевой колонки вызывается `str.replace('"', '')`. Результат снова экспортируется в `|`‑формате без кавычек.
- **Oграничения**: ожидается, что входной файл уже использует `|` в качестве разделителя; иначе структура сломается (описано в разделе «Ошибки и ограничения»).

### 🏷️ Теги (`tabs[6]`)
- **Назначение**: привести набор тегов каждой строки к 5 релевантным значениям из списка Allowed Tags.
- **UI**: `text_area` для Allowed Tags (обязательное поле), кнопка загрузки списка моделей, слайдеры параметров, загрузчик CSV (обязательная колонка `tag`), настройка `max_workers`.
- **Валидация**: при пустом списке Allowed Tags выполняется `st.warning` и `st.stop`, что предотвращает дальнейший рендер (см. раздел ограничений). При отсутствии колонки `tag` выводится `st.error`.
- **Алгоритм**: для каждой строки формируется промпт, где перечислены Allowed Tags и текущие теги. `chat_completion_request` генерирует ответ, который через `custom_postprocess_text` нормализуется и приводится к 5 тегам (лишние отбрасываются). Параллелизм достигается через `ThreadPoolExecutor`.
- **Выход**: новая колонка `final_5_tags`, CSV доступен для скачивания.

## 🧹 Правила постобработки

При запуске вкладки “Постобработка” к пользовательским паттернам добавляются автоматические проверки:

- Удаление всех эмодзи, китайских и иных CJK‑символов.
- Очистка доменных имён с `.com` и `.net`, включая вводки “See full version …”.
- Вырезание служебных комментариев модели, начинающихся с `Error`, `Note`, `However`, `Sorry`, `<tool>`, `direct link`, `I can't`.
- Замена `Mother`, `Father`, `Brother` и т.п. на step‑аналоги (`StepMother`, `StepFather`, …).
- Фильтрация символов `><"№;%*/\{}` и попытка автоматически восстановить пропавшие пробелы между словами.
- Усечение заголовка до 100 символов (по границе слова), если детектирован “хвост” с пояснениями.

Результат пишется в новую колонку `cleaned`.

| Тип | Ограничения | Дополнительно |
|-----|-------------|---------------|
| CSV | Разделитель определяется автоматически (кроме вкладки удаления кавычек, где ожидается `|`). | Файл читается в `pandas.DataFrame`. |
| TXT | Любой текстовый файл, построчную структуру задаёт параметр “Разделитель”. | Для табличных данных необходимо вручную перечислить названия колонок. |

## ⚖️ Настройки генерации

- **Presets** (`PRESETS`) содержат наборы значений `system_prompt`, `max_tokens`, температур и штрафов.
- Любой параметр можно донастроить через слайдеры/текстовые поля.
- При работе с большими файлами выбирайте в слайдере `max_workers` оптимальное число потоков, чтобы не ловить rate-limit 429.

## 🚨 Найденные ошибки и ограничения

1. **Жёстко захардкоженный API ключ** (`DEFAULT_API_KEY` в `app.py`). Файл под версионным контролем, ключ видит любой пользователь. Рекомендуется читать ключ из переменной окружения или `st.secrets` и удалить значение по умолчанию.
2. **`st.stop()` на вкладке “Теги” останавливает всё приложение**, если поле Allowed Tags пустое. В текущем виде остальные вкладки не отрисуются, пока пользователь не введёт теги. Нужно заменить на ранний `return` внутри блока или условный рендер без вызова `st.stop`.
3. **Чтение CSV на вкладке “Удаление кавычек” жёстко привязано к разделителю `|`.** Если пользователь загрузит стандартный CSV с запятой, произойдёт разбор с ошибкой или некорректная структура. Следует либо автоматически определять разделитель, либо запрашивать его у пользователя.

---

## 🔧 Полезные советы

- Для работы с файлами более 50k строк используйте маленький `chunk_size` и больше потоков.
- Храните пресеты в `.yaml` или `st.session_state`, если планируете расширять список моделей.
- Добавьте кэширование (`st.cache_data`) для списка моделей, чтобы не дергать API по каждой перезагрузке страницы.
